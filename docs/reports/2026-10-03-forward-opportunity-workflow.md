## 参考对话中的可靠性问题

对话给出了“背景条件 -> 催化事件 -> 资金传导 -> 价格确认”的有用组织方式，但没有给出多数具体日期、价格涨幅、仓位与资金流数字的原始出处；9 月 21 日也没有明确年份和图表时区。不能把整段解释直接放入冻结事实集。

- COT 通常周五发布前一周二的持仓快照，并有节假日延期；它不能作为当天实时空头仓位。[CFTC 发布说明](https://www.cftc.gov/MarketReports/CommitmentsofTraders/index.htm)。
- 指数调仓涉及买入和卖出，生效时间与实际执行时间需要分别核对；不能推导出“周一必有指数净买盘”。Nasdaq 说明基金会按生效前一交易日收盘价格调整跟踪。[Nasdaq 指数构建说明](https://www.nasdaq.com/articles/ingredients-index-construction)。
- 台积电公开月报主要是公司总营收及同比/环比，不能单凭月报推出 CoWoS、HPC 分项收入或客户未来订单。[TSMC 月度营收](https://investor.tsmc.com/english/monthly-revenue)。
- “到期后必然趋势行情”“收益率和油价下行必然利好科技股”“净流动性固定滞后 10–15 天”“CTA 必买具体金额”均应视为待检验的条件性假设。供应商或投行模型估计、公开观测、AI 推断需要分别标记。

## 当前系统的能力与缺口

现有流程具备采集、事实压缩、行情、量化、研究共识、主审、执行共识和硬风控。`ANALYSIS_ONLY` 仅走研究分支；常规研究有独立的模拟验证分支。已存在持久化 Forecast 和评估入口。

Quant 当前主要为均线、突破、均值回归、RSI、量价和组合信号；指标覆盖 MACD、ATR、布林带和支撑阻力。这些用于确认和交易时机，但尚不能直接验证产业传导、预期差、资金约束等前置机制。

宏观数据目前仍以通用信息源和文档进入系统；经济日历、公布值/修订、市场预期快照和历史可知版本仍是待实施方案。机会假设生命周期已保存到独立账本，尚未建立自动条件验证和有效性样本。SDB-SCA 的严谨投票不能代替事实可靠性、预测校准或盈利验证。

## 推荐流程

`用户指定商品 -> 关联观察数据 -> 前置假设 -> 情景与反证 -> 持续验证 -> 机会成熟度 -> SDB-SCA -> 主审/执行/风控 -> 本地模拟 -> 复盘`

### 1. 先建立三条持续运行的研究节奏

| 节奏 | 研究问题 | 输出与触发 |
|---|---|---|
| 每周/每日 | 哪些背景变化可能在未来数天或数周传导？ | 有证据的机会假设、潜在催化日历、待验证数据 |
| 数据或事件变更 | 哪条假设被加强、削弱或推翻？ | 更新原假设，保存版本和概率变化理由 |
| 临近催化/交易时段 | 兑现是否已经发生，价格和成本是否仍适合？ | 确认条件、放弃条件和模拟执行候选 |

常规观察和阈值判断使用确定性计算；只在新证据、催化接近或状态变化时调用完整 AI 面板。一次深度研究仍只处理一个商品，共享事件和宏观事实可以复用。

### 2. 每个假设必须形成可追踪记录

最小字段：关联商品、首次提出时间、证据与可知时间、因果链及每条边的依据、必要条件、候选催化及窗口、市场已有定价的观测、替代情景、方向概率、触发条件、失效条件、有效期、下一次检查项、缺失数据、关联敞口、版本。

状态建议：`待验证 -> 观察中 -> 临近催化 -> 已确认 -> 模拟验证 -> 完成`；任何阶段可转为 `被反证 / 已过期`。早期假设进入观察列表，不因论证漂亮就生成挂单。

事实、供应商估计、代理指标和 AI 推断分别标记；没有市场一致预期时保留空值，不能用 AI 预测冒充一致预期。时间记录至少区分事件发生、官方发布、系统获得和研究决策时间。数据修订追加版本，回放只能读取当时可获得的版本。

### 3. 明确“提前几步”的含义

- 一步：已公布信息与尚未充分反应的价格之间存在待验证差异。
- 两步：已观察到上游变化，推演其如何影响盈利、政策预期或资金需求。
- 多步：继续追踪必要条件与传导时间，给出多个分支；每增加一层都展示额外假设和不确定性。

提前时间越长，证据与入场时机越需要分开。更多链条不等于更高胜率；不能把存在相关性的条件概率直接相乘，更不能把未来步骤写成已经发生的事实。

### 4. 在现有五角色中调整研究问题

| 现有角色 | 增加的任务 |
|---|---|
| 证据分析 | 审核可知时间、事实来源、数据修订和缺失，提出需要补查的上游数据 |
| 看多分析 | 提出未兑现的上行情景及必要条件，说明已被价格反映的部分 |
| 看空分析 | 提出下行情景与能够推翻上行情景的观测，避免被固定看空立场约束 |
| 市场结构 | 区分真实仓位/订单流和模型代理，检查资金传导、拥挤、跨资产与合约基差 |
| 风险控制 | 检查期限、赔率、成本、失效、模型不确定性和组合重复敞口 |

仍允许一角色多席位，角色内使用不同模型。独立提出假设后再匿名互评；失败、被淘汰、无共识的假设也保存，便于统计误报。最终交易审核关注条件是否成熟、成本与风险是否允许；研究价值评估关注假设是否提前、可靠且提供新信息。

### 5. 对 NAS100.s / QQQUSDT 的示例

以下是流程示例，不是当前交易建议：

`存储厂商公开订单/盈利指引变化 -> 验证 MU/SKHYNIX/SNDK 的受益差异 -> 检查是否属于广泛科技盈利变化 -> 纳指相关权重与利率情景 -> NAS100.s/QQQUSDT 可能的反应`

反证包括：变化仅局限个别公司、利好已反映、利润被成本吞噬、需求转弱或贴现率上升。明确下一份财报/宏观发布/公司公告的核对条件；不同商品分别使用其实际行情和成本，纳指方向假设不能直接复制成所有芯片商品的买入信号。

## 评估与实施顺序

评估必须同时记录正确和错误假设：首次提出到触发/行情变化的提前量、误报率、机会覆盖率、Brier/log loss、概率校准、过期率、反证识别速度、扣成本后的收益与回撤。按同一宏观事件或同一市场冲击分组，避免把 NAS100.s 与 QQQUSDT 等案例当作独立样本。

与当前趋势跟随/单模型/独立多模型基线使用同一时点、同一可知数据和同一成本口径比较。前瞻观察优先；历史回放也须检查数据版本和模型对历史事件的记忆泄漏。

1. 完成用户指定商品、真实行情、本地模拟和事件账本，作为验证底座。
2. 补齐中美经济日历、公布与修订数据、证据可知时间；新增机会假设及状态看板。
3. 先接入官方、可持续获取的行业财报/公告、利率和 COT 等数据，再评估期权仓位、CTA 测算等需要授权且口径复杂的数据。
4. 在纯分析范围前瞻收集 30–50 个案例，验证流程和度量，再估计正式样本量；该数量不构成盈利证明。
5. 有增量证据后才调整策略和模拟执行准入，保留版本与回滚入口。

方案涉及新增数据/API 契约，具体实现需按任务范围确定；本报告不改变已发布工作流、模型席位、交易授权或模拟账户。
