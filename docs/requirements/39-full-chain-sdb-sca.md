# 全链路 SDB-SCA 决策面板需求

## 目标

将 SDB-SCA 从研究辩论扩展到所有会改变事实集、研究结论或交易动作的 AI 阶段，形成：

`证据互证 -> 研究共识 -> 主审共识 -> 执行共识 -> 硬风控 -> OMS`

系统不得在任一阶段退化为“单个模型最后总结并覆盖前序结果”。高能力模型可以作为席位，
但终局状态、方向、数值和是否执行必须由对称协议与确定性规则产生。

## 面板类型

### EVIDENCE

- 清洗与压缩席位对同一冻结原文独立提取事实，不生成文章摘要。
- 双盲互审遗漏、重复、冲突、时效和引用归属，再对各自事实集做隔离修正。
- 确定性 reducer 以 canonical fact key、来源独立性、时间一致性和引用覆盖率生成事实集。
- 无法消解的冲突必须保留为显式冲突事实，不能由 LLM 静默选边。

### RESEARCH

- 延续 `SDB_SCA_V1` 的独立提案、双盲评审、隔离修正、正反序选票和 Schulze 聚合。
- 多模型席位按 `logicalRoleKey` 归一，任何模型副本数量不能扩大角色投票权。
- 输出方向概率、预测区间、失效条件、证据引用和严格共识状态。

### PRINCIPAL_REVIEW

- 输入只包含冻结事实集、量化结果和研究共识，不读取执行计划。
- 席位至少覆盖证据审计、反例审计、市场结构、风险与可执行性。
- 主审只能确认、收紧或拒绝研究共识，不能凭空创造新产品、方向或证据。
- 无严格胜者、顺序敏感、低 quorum 或关键证据冲突时输出 `NO_ACTION`。

### EXECUTION

- 输入只包含已通过主审的共识、实时模拟盘报价、账户状态和确定性风险预算。
- 席位独立提出仓位、杠杆、订单类型、入场、止盈、止损和失效/撤单条件。
- 双盲评审重点检查滑点、费用、流动性、强平距离、交易所规则和客户端幂等性。
- reducer 只能在主审方向与风险预算内选择计划；不能扩大风险、切换产品或反转方向。
- 最终计划仍须通过 `RiskPolicy`、交易所 capability、余额/仓位和 OMS 幂等门禁。

## 统一协议不变量

1. 每个面板使用独立冻结输入、独立 `panelKey` 和独立持久化会话。
2. 同阶段产物封存到 barrier 后原子揭示，禁止先完成席位泄漏给后完成席位。
3. 候选、评审、修正和选票全部匿名，不向模型暴露 Provider/Model/Role 身份。
4. 相同逻辑角色的多个异构席位总权重恒为 1。
5. 所有 reducer 必须确定性、置换不变、可重放，并永久记录输入哈希与决策哈希。
6. 面板之间只允许单向传递已完成的 canonical artifact，禁止下游反向改写上游事实。
7. 任一面板失败关闭时，下游只能生成 `WATCH / NO_ACTION`，不能通过 fallback 绕过。
8. UI 展示结构化结论、反例、证据、票矩阵和失败原因，不展示隐藏思维链。

## 工作流配置

- 节点新增不可变 `panelKey` 与 `panelPurpose`，同一工作流可配置多个面板。
- 每个面板拥有独立参与席位、quorum、超时、评审分配、reducer 和成本上限。
- Provider/Model/Reasoning 仍按席位自由配置，并要求多 Provider/模型混合。
- 默认主工作流启用 EVIDENCE、RESEARCH、PRINCIPAL_REVIEW、EXECUTION 四个面板。
- 自定义工作流可关闭非交易面板；任何自动交易工作流不得关闭主审和执行面板。

## 状态与恢复

- 一个 workflow run 可拥有多个 panel session，唯一键为 `(runId, panelKey)`。
- task/artifact/candidate/ballot/decision ID 必须包含 panel identity，跨面板不得冲突。
- Worker 重启按面板 barrier 恢复；已完成上游面板不可重新生成或被下游修改。
- 执行面板完成后才允许创建 durable trade decision；订单提交结果未知时沿用 OMS 对账恢复。

## 验收标准

1. 四类面板均具备顺序置换不变测试、低 quorum/并列/顺序敏感失败关闭测试。
2. 主审无法引入研究共识之外的新方向、产品或证据引用。
3. 执行面板无法突破主审方向、`RiskPolicy` 或交易所 capability。
4. 同一 workflow run 的多个面板可独立恢复，ID、候选和选票不串台。
5. 旧 `LEGACY_CHAIR_V1` 与顺序 DRAFT/REFLECTION 记录可读，但新默认运行不再调用。
6. 生产 TestNet 真实链路能看到每个面板的 barrier、共识状态、最终计划和 OMS 结果。

## 非目标

- 不让 LLM 替代确定性风险引擎、交易所校验、余额校验或 OMS。
- 不引入 Redis、MQ、分布式锁或多副本协调。
- 不把模型原始隐藏思维链持久化或展示给用户。
- 不在本阶段接入真实资金交易。
