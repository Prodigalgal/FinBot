# Bybit TradFi 本地模拟执行

## 目标与范围

用户于 2026-10-03 最终补充：指定商品同时覆盖 Bybit USDT 永续及 `NAS100.s` CFD。使用 Bybit 生产公开行情，由 FinBot 持久化模拟挂单、成交、持仓和费用，验证研究决策在市场中的表现。既有 Bybit Demo 账户同步与交易所模拟执行保留。

交易商品由用户指定。当前名单为 `BTCUSDT`、`ETHUSDT`、`DOGEUSDT`、`XAUUSDT`、`SKHYNIXUSDT`、`SNDKUSDT`、`MUUSDT`、`QQQUSDT` 和 `NAS100.s`。调度从默认自选列表中的显式映射读取，一次研究一个商品，逐一执行；AI 不新增交易商品。用于推演的宏观、产业、其他资产数据可以超出交易名单。

沿用 `canonical_product -> venue_instrument`、已持久化的单产品研究范围、执行审核和风险策略。现有 `ESTIMATED` 只保存预估计划；本能力把通过既有审核的预估计划推进为独立的本地模拟生命周期。分析聊天仍为 `ANALYSIS_ONLY`。

## 执行边界

- 本地模拟使用独立虚拟 USDT 账户，不借用 Bybit Demo 余额，不创建交易所私有请求，不改变 `venue_instrument.execution_enabled` 来伪装交易所执行能力。
- 行情来源为 Bybit `LIVE` 公共市场；执行方式明确标为 `LOCAL_PAPER`。来源环境与执行方式分别保存，不能把 LIVE 行情标成交易所 Demo 成交。
- 永续和 CFD 使用不同的行情、合约及费用适配，保留 `NAS100.s` 的大小写和 CFD 类型。产品和映射均须 ACTIVE，并明确选择启用本地模拟。
- 自动挂单只消费启用后新生成、仍有效的研究预估计划，保留研究范围、执行审核、风险策略版本及成本参数。历史预测和旧预估不自动变成订单。
- 同产品不能重复占额；虚拟可用余额、未成交挂单和持仓共用仓位/保证金约束。暂停新订单不丢弃已有持仓管理。

## 行情与撮合

定时任务仅读取有挂单或持仓的标的，批量/复用行情请求；沿用现有后台任务租约、重试和出站路由。行情包含来源时间、获取时间、bid/ask、成交价、标记价及原始证据；数据缺失、过期或未来时间戳禁止生成成交。

限价买入依据 ask、限价卖出依据 bid 判断，触价只代表模型条件满足。挂单成交在限价内；市场退出按可观察的买卖报价和不利滑点计算，跳空止损不保证按止损价成交。成交记录标注模拟模型和依据，不能把价格触及宣称为真实排队成交。

使用下单后可用的分钟 K 线补查轮询间遗漏的行情；下单所在 K 线包含下单前数据时不得用全柱高低价回填成交。只有 OHLC 而无法确定入场、止盈和止损先后时，采用明确的保守规则并保存歧义标记。数据缺口超过可验证的回补范围时暂停撮合并展示原因，不补造盈利。

## 资金与恢复

独立保存订单、成交事件、仓位、资金流水、撮合游标和策略版本；同一行情/资金费时点重复消费不能重复成交或扣费。每次状态推进及余额变化在短事务内完成，HTTP 请求在事务外。并发任务通过账户锁和版本校验协调。

手续费与滑点参数按订单冻结。资金费按该合约的实际历史时点、费率和持仓方向计入，费率正负均保留；未知费用不能当作零并宣称净收益完整。持仓估值使用标记价，强平仅作为明示的模拟风险模型。

挂单可取消、可到期；持仓支持止盈、止损和显式模拟平仓。重启后从持久化游标恢复，不重新调用 AI、不重建旧订单。账户看板分别显示余额、占用保证金、未实现/已实现盈亏和手续费/资金费；交易所 Demo 与本地模拟分别统计。

## CFD 接入要求

`NAS100.s` 的一手报价和合约元数据来自 Bybit CFD 页面实际使用的公开接口。2026-10-03 检查确认合约单位 1、最小手数 0.1、递增手数 0.1、价格 tick 0.01；这些是核对快照，运行时仍须检查元数据变化。

CFD 须识别服务器冬夏令时、周末/每日交易间断、实际 bid/ask、报价时点、手数和 USD 隔夜费；不能把 MT5 tick volume 作为可成交数量，不能用 `QQQUSDT`、其他纳指报价或 V5 永续数据替代。缺少实际报价时点、历史数据或适用费用版本时，明确展示阻断原因。模拟值采用明确的 USDT/USD 1:1 估值假设，不能冒充交易所 USDx 实际余额。

公开网站接口没有 V5 的稳定 API 契约，须保存来源、严格检查响应、测试错误/缺字段/休市及变更行为，并提供失败关闭与恢复路径。

## 影响与验收

- 影响：paper simulation 领域与应用端口、JDBC/Liquibase、Bybit 公开行情适配、后台任务、管理 API/OpenAPI、交易工作台；沿用 Java/Spring、React 和现有认证。
- 验收：下单到成交再到退出/账本可追踪；方向、步长、额度、重复请求、并发、取消、到期、跳空、同柱歧义、数据缺口和重启均可验证；交易所私有调用次数为 0；聊天不创建模拟订单。
- 验证：确定性撮合与成本单测、真实 PostgreSQL 事务/幂等测试、契约和 Web 测试/构建、完整 CI、GitOps、当前 Bybit 公开行情及后台状态验收。
- 回滚：关闭本地新单开关；保留事件账本和持仓状态。应用回退前须暂停新调度类型，新增表保留。默认工作流、Demo 账本和历史预估可继续读取。
